=> NO kernel write is needed. The only flash write is erasing ONE 64 KB block of mtd0 (offset 0x30000 = 196608, the U-Boot env block).

PRE-FLIGHT (read-only on unit)
 1. Wall power, nothing else on the supply. SPI programmer + clip ready, full_16MB_for_programmer.bin on the host.
 2. Re-pull mtd0 and mtd1 over ssh; sha256 must equal SHA256SUMS (mtd0 e62f62a9..., mtd1 738af784...). Any change since backup -> stop and re-backup.
 3. scp round_trip/flash_erase to unit:/tmp, chmod +x, run it with no args (usage text only). The OCBM unit has no flash_erase/flashcp.

WRITE (single step; point of no return = the erase)
 4. /tmp/flash_erase /dev/mtd0 196608 1 && sync
 5. Re-pull mtd0: bytes [0x0,0x30000) must equal backup; [0x30000,0x40000) must be all 0xFF. If not -> do NOT reboot; restore with the programmer.
 6. reboot. Expect two resets (U-Boot converts the 3 staging blocks at flash 0x342fd8/0x352fd8/0x362fd8 -> 0x40000/0x50000/0x60000, then rewrites env). Wait up to ~90 s for 192.168.50.2.

PASS CRITERIA (all must hold)
 - unit returns on NCM and boots the normal OCBM userspace;
 - mtd1 re-dump sha256 == 738af784df8c536026f6f834c5bb5fb8b747fc03bddc6c12839999411d84d128 (conversion is deterministic);
 - mtd0[0:0x30000) unchanged; env block (0x30000..0x40000) no longer all 0xFF.
FAIL -> SPI-restore full_16MB_for_programmer.bin (erase chip first).

UNVERIFIED ASSUMPTIONS (state before running)
 - that U-Boot with an erased env block falls back to the update-block env and runs heweiencrypt (taken from LIVI's flow/comments, not from U-Boot disassembly);
 - that conversion is power-loss safe because the env is rewritten last (inferred, untested);
 - that the stock flash_erase runs against this unit's glibc 2.20 and accepts byte offset 196608.

RESULT (run 2026-10-19 ~16:52-16:55 local, owner accepted risk, no programmer on hand): PASS
 - pre-flight: mtd0/mtd1 re-pulled, sha256 == backup. flash_erase 1.4.8 pushed to /tmp, ran (usage), accepts "<start offset> <block count>".

LIMIT: this proves U-Boot rebuilds its env after the erase and the kernel is intact.
